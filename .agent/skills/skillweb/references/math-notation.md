# 수식 렌더링 — MathJax

강의자료·기술문서형 인풋(§5)처럼 수식이 많은 콘텐츠는 `v = N·dφ/dt`, `Z_in = n²·Z_L` 같은 걸 유니코드 기호로 흉내내지 말고 MathJax로 실제 LaTeX 렌더링한다.

## 1. CDN 스니펫 (그대로 `<head>`에 삽입)

```html
<script>
  window.MathJax = {
    tex: { inlineMath: [['\\(', '\\)']], displayMath: [['\\[', '\\]']] },
    svg: { fontCache: 'global' }
  };
</script>
<script src="https://cdn.jsdelivr.net/npm/mathjax@3/es5/tex-svg.js" async></script>
```

본문에는 `\( ... \)`(인라인), 독립된 수식 줄에는 `\[ ... \]`(디스플레이)를 쓴다.

## 2. 슬라이드 전환과의 상호작용

MathJax는 페이지 로드 시 DOM을 한 번 스캔해서 렌더링한다. 슬라이드가 `display:none`으로 시작해도 텍스트 노드 자체는 DOM에 존재하므로 초기 렌더링은 문제없이 된다 — `slide-enter`에서 다시 트리거할 필요 없음. 단, JS로 수식 텍스트를 **동적으로 삽입**하는 경우(예: 예제 슬라이드를 템플릿에서 생성)에는 삽입 후 `MathJax.typesetPromise([그_요소])`를 명시적으로 호출해야 렌더링된다.

## 3. `<`/`>` 이스케이프 — 실제 사고로 확인된 버그

부등호가 들어간 수식(`\(-1<x<1\)` 등)을 이스케이프 없이 그대로 HTML 텍스트에 넣으면 안 된다. `<` 바로 뒤에 알파벳이 오면(`<x`, `<t`, `<n`...) 브라우저 HTML 파서가 이걸 새 태그의 시작으로 오인해서, 그 뒤에 오는 진짜 `</h2>` 같은 닫는 태그까지 통째로 다음 태그의 속성으로 먹혀버린다 — 결과적으로 그 제목 전체가 MathJax 렌더링도 안 되고 화면에 날것 그대로(`\(f(x)=x,\ -1<x<1\)...`) 깨져서 나온다. (`<` 뒤에 숫자나 공백이 오는 건 안전 — HTML5 파싱 규칙상 태그 이름은 알파벳으로만 시작하기 때문에 `<1`, `< x` 같은 건 파서가 그냥 리터럴 텍스트로 처리한다. 위험한 건 오직 `<` 바로 뒤에 알파벳 변수명이 붙는 경우다.)

**고치는 법**: 수식 텍스트 안의 `<`/`>`는 항상 HTML 엔티티로 이스케이프한다 — `\(-1<x<1\)` → `\(-1&lt;x&lt;1\)`. MathJax는 엔티티를 정상적으로 LaTeX `<`로 되돌려 렌더링하므로 결과물은 동일하고, HTML 파싱만 안전해진다.

## 4. 예제 풀이 슬라이드 표기 규칙

§5의 "예제는 실제 숫자로" 규칙과 함께 쓴다 — 입력값/중간 계산값 모두 `\(...\)`로 감싸 MathJax가 렌더링하게 하고, 페이저 표기(`120∠0°V`)처럼 MathJax가 기본 지원하지 않는 기호는 `\(120\angle 0^\circ\,\text{V}\)` 형태로 LaTeX 명령(`\angle`, `\circ`, `\text{}`)을 써서 표현한다.
